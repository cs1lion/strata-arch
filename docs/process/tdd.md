# 分层 TDD 流程

适用：Strata 从 ticket 02 起的实现与验收。ticket 01 为历史例外，见文末。

## 档位与适用范围

### A — 严格 TDD（红 → 绿 → 重构）

适用于纯逻辑与契约：CLI 契约、模块解析、符号提取与调用图、层推断、引导式路径查询、git 历史指标、图算法。

要求：

1. 先写失败测试，再写实现；一次只增加一个失败断言。
2. 测试只断言外部可观察行为（CLI JSON、core 公共 API、golden 边集合），不断言私有实现。
3. 固定 fixture / 样本仓 + golden 断言；缺边、多边、错归属、计数漂移都必须判红。
4. 保留三段证据：Red、Green、Refactor。证据必须是实际命令输出，禁止事后编造或把实现后补的测试冒充红绿。
5. golden 首次生成需人工抽检并签字；任何 golden 变更必须在汇报中写明原因。

汇报模板：

```text
TDD 档位：A
Red:    <命令> → <失败断言名 + 期望/实际读数>
Green:  <同一命令> → <通过读数>
Refactor: <命令> → <仍通过读数；若无重构写「无」>
```

### B — 断言先行（不强制红绿）

适用于 GPUI 布局、绘制与交互外观：节点矩形、边端点、标签包围盒、z-order、命中框、截图、播放状态。

要求：

1. 实现前先写结构断言清单，并说明每条断言对应哪个可见行为。
2. 允许视觉细节迭代，但不允许为了通过测试迁就实现、放宽阈值或删掉断言。
3. 像素差门禁默认关闭（待用户确认）；结构断言必须开启。
4. 不需要伪造 Red；但汇报必须给出「断言先于实现」的证据（提交顺序、测试文件时间戳或先行清单记录）。

汇报模板：

```text
TDD 档位：B
断言先行清单：节点矩形 N 条、边端点 N 条、标签包围盒 N 条、z-order、命中框 N 条、截图非空
执行：<命令> → <通过读数 + 截图/结构断言摘要>
视觉迭代说明：<调整了什么，断言未变/为何变更>
```

### C — 预算先行

适用于性能、内存与时间预算：ticket 10（索引/历史/内存）、07（帧预算）、08（历史墙钟）、11（启动时限）。

要求：

1. 实现前先把预算钉死：指标、阈值、测量命令、样本仓与 commit、运行次数、硬件基线。
2. 读数必须实测并保留原始输出；用预期值或估算值替代视为未通过。
3. 超预算判红，不得在看到读数后回调阈值；确需调整阈值必须单独说明并征得确认。
4. 默认 3 次运行，记录每次读数、中位数与 p95，并附硬件信息。

汇报模板：

```text
TDD 档位：C
预算：<指标> ≤ <阈值>；测量：<命令> × 3；硬件：<CPU/内存/OS>
实测：run1=<读数> run2=<读数> run3=<读数>；median=<读数> p95=<读数>
结论：通过 / 未通过（<超出的具体读数>）
```

### 不适用

- ticket 12 可用性任务测试：人工协议 + 证据归档，不做自动化 red/green。
- ticket 13 探索式交互占位：只写占位文档，不实现。
- 纯文档改动。

## 共同约束

- 每张 ticket 的汇报必须标注档位；A 附 Red/Green/Refactor，B 附断言清单与执行读数，C 附预算声明与实测读数。
- 不得为了让测试变绿而降低验收标准；验收标准本身有歧义时停下来反馈。
- 不得改写已通过的历史实现来「补齐」流程；历史缺口如实记录为例外。
