## 问题

09 已经能拖动刻度查看「截至某提交」的模块热力，但只能一格一格点。用户无法连续观察结构的演化节奏：

- 哪些模块是在同一轮提交里集中出现的？
- 某条层的边是逐步长出来的，还是一次性爆炸？
- 热力（churn/commitCount）的上升与模块新增是否同步？

静态拖拽能回答单点，不能回答「过程」。

## 方案要点

- 在 09 的 `TimelineState` 之上增加播放器：播放/暂停、速度（例如 0.5×/1×/2×）、单步前进/后退、跳首尾。
- **指标只做离散切换**：`lastModified`/`count`/`churn` 在刻度之间不插值，避免「看起来连续但数值不存在」。
- 视觉过渡可以有：节点位置、透明度、颜色可做短插值（≤200ms），但每个刻度的真值以离散产物为准。
- 采样策略：优先复用已采样的前缀产物；大仓改为「按需采样 + 缓存」，并在视图上显示 `degraded` 与已采样刻度数（与 09 的 `truncated`/`sampled` 标记一致）。
- 复用 07 的 `PlaybackState` 状态机语义（`current` = 已推进步数、默认不循环、结束停在末帧），不另造一套。
- 帧预算：单帧模型更新 p95 ≤16.7ms（口径同 07，明确只测状态更新，不测 GPU 渲染）。

## 可执行验收判据

1. 播放 N 步后 `current == N`；暂停后再播放从当前刻度继续；回退在 0 时失败且状态不变；结束停在最后一帧，不循环。
2. 任一刻度暂停时，面板读数与直接 `scrub_to(k)` 完全一致（禁止插值指标；断言数值相等）。
3. 模型单帧更新 p95 ≤16.7ms（20 步合成样本，微秒级计时）。
4. `truncated`/`sampled` 存在时，视图必须显示 `degraded`，且不允许把未采样刻度伪装成完整历史。
5. 播放/暂停/退出后重新进入，状态可复现（同一刻度同一读数，字节级 JSON 对比）。
6. 反向用例：刻度缺失（历史采样空洞）时跳到该刻度必须显式提示，不得静默沿用上一刻度读数。

## 成本区间

中等：状态机可复用 07，主要成本在「大仓按需采样 + 缓存」与 UI 动效。粗估 M；若只做小仓固定样本，可降到 S–M。
