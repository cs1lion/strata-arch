# 27: 边可见度分层（弱边降级 + 播放态只画路径/当前边）

**状态**：done-with-gap（渲染侧改动已落地 `2c8f830`；**画面效果的像素级验证待用户授权一次抓屏**，P1 读数需重基线）。

**What to build:** 让地图从"一堆方块 + 一团灰线"变成有层级的图：普通浏览时边只作背景骨架，播放路径时只强调路径/当前边、不再把 4363 条上下文边糊在画面上。不改变任何判据阈值，不改变 `playback` 模型层的透明度语义。

## 2. 立项依据：杂乱连线的只读量化

headless 复现 `layout_map` 坐标（`LayoutConfig::default()`：`width=1200`、`node 150×40`、`gap_x=12`、`gap_y=10`、`band_header=24`、`band_padding=10`、`band_gap=16` ⇒ `columns=7`），再对边做线段求交与矩形穿越检测：

| 指标 | 实测 |
| --- | --- |
| 模块边数 | 4363 |
| 交叉对 | **1,802,340** |
| 穿过第三方节点的边 | **4125 / 4363 = 94.5%** |
| 带内边 | 1843（42.2%），**平均跨 5.86 行** |
| 跨 ≥2 带边 | 2027（46.5%），平均纵向 **3124px**（画布高 6200px，节点高 40px） |
| 最大带 | `components` 285 节点 = **41 行** |

**两个被实测否掉的直觉**（写下来防止后人重做）：

- 带内按邻居重心排序 ×3 轮 ⇒ 交叉只降 **1.5%**，穿节点反而 **+3.8%**。**节点顺序不是原因**。
- 端点从节点中心裁到矩形边界 ⇒ 交叉降 **20.1%**，但穿节点 **0% 改善**。有帮助，不是解药。

**结构性原因（代码级，本笔只处理"可见度"这一层）**：

1. `arch_view_canvas.rs` / `main.rs::edge_canvas` 的路由控制点**只按 dy 竖向偏移**（`offset_y = (|dy| × 0.45).clamp(24z, 140z)`），横向无任何通道/泳道分配 ⇒ 边必然横穿网格。
2. 边端点取**节点中心**（`viewport.screen_point(edge.from/to)`）⇒ 线段必然进入节点内部（对应 94.5%）。
3. 弱边**同色同宽同 alpha 1.0** ⇒ 数千条叠成雾（本笔处理对象）。
4. 布局本身是 8 带竖排、每带最多 41 行的稠密网格。

## 3. 本笔做了什么（`2c8f830`）

- 新增 `EDGE_PLAIN_OPACITY = 0.35`：普通浏览时全部边的 alpha 上限（原为硬编码 1.0）。
- 新增 `show_context_edges()` 读 `STRATA_SHOW_CONTEXT_EDGES`（默认 false）：播放态不再绘制上下文边。
- 模块视图 `base_opacity` 三态分派（播放态隐藏 / 普通浏览降级 / 搜索态**保持原样不动**），并在 opacity 算完后 `if opacity <= f32::EPSILON { return None; }` 提前剔除，使隐藏边不进入批量路径构建。
- 符号视图加同一策略的 `.filter`（播隐藏非 strong 上下文边，保留 Current/Path）。
- theme 弱边线宽 `1.25 → 0.95`（strong 2.15 / adjusted 1.75 不动）。
- 删除面如实：`main.rs 36/2`、`arch_view_theme.rs 2/1`，共 **3 行**（`base_opacity` 两行 + 线宽一行），其余纯插入。

**刻意没做的**：不改 `playback.rs` 的 `EdgeRole::opacity` / `edge_context_opacity`（`context_fade.rs:174-190` 断言透明度只能取 `{1.0, 0.68}` 且禁止回落 0.25，属票 16 冻结语义）；不把开关塞进 `RenderTuning`（`for_segment` 有 base/A/B/BA/AB 五处逐字段字面量，且会污染票 23 的 A/B 配对矩阵）；不动任何阈值与判据；不新增守护项。

## 4. 对既有判据的影响（必须重基线）

- **P1（票 16/24）**：票 24 已登记的绿读数 `changed=7.968%、hotCells=439、meanMax=22.32` 是 **`c6de9af` 时代**的测量。本笔让"播放态上下文边消失"，off/on 两帧的差会**进一步变大**（边本身就是像素差来源之一）⇒ **该读数不再是当前值**，重基线前不得引用为当前事实。属被测对象真实改变，**不得**为此调任何阈值。
- **搜索五态（票 20）**：搜索聚焦分支未改动，边可见度仍由 `set.edge_opacity(...)` 决定 ⇒ 预期不变；但 `off/results/noMatch` 面板判据是**像素统计**，弱边整体降级会轻微改变面板区域内的底色像素计数 ⇒ 需在同一次抓屏中复核（属"验证"，不是"调阈值"）。
- **`static-baseline-noise` / `p3-*`（timeline 视图）**：不经 map 边链路 ⇒ 不受影响。
- **`diff-*`（DiffView）**：其 `fade_enabled` 是另一条 CLI 字段链路 ⇒ 不受影响。

## 5. 遗留（按优先级）

1. **抓屏重基线**（待授权，一次）：给 P1 与搜索五态的新读数 + 前后对照图；须附 `gt0/gt1/gt6/gt12/gt24` 与 `meanMax` 分档，并确认 `p1-frames-settled` 为真。
2. **渲染侧 alpha 无测试覆盖**：若要把"边可见度层级"变成可守的，需像 `apply_fade_alpha` 那样把策略提取为 lib 纯函数再加测试（本笔按指示未新增守护）。
3. **路由层未动**：`edge_canvas` 的 `offset_y` 只看 dy、端点取中心 ⇒ 真正的去杂乱需要"带配对走廊分配 + 边界锚点"（量化：端点裁剪 −20.1% 交叉；走廊未测，需先做一个可复算的路由原型）。
4. **同型 alpha 乘法点仍有三处未审视**：`main.rs` 的另外三处 `a *= opacity`（层带、双色绘制点、另一三色绘制点），本笔只处理节点与边链路。
5. 符号视图播放态边是否与模块视图观感一致，未做人工核对（需抓屏）。
