## Problem Statement

开发者第一次进入一个陌生 TS/JS 仓库时，缺少一条低成本的路径来回答三个问题：系统由哪些模块和层组成、一次调用实际经过哪些代码、哪些部分是长期演进的核心而哪些多年未动。现有工具要么只给静态依赖图（很快就变成不可读的「毛线球」），要么需要上传代码、配置服务或在 IDE 里逐文件跳转；它们都不提供「从入口到目标」的引导式解释，也不把 git 历史作为结构理解的一部分。

结果是上手会话只能靠反复跳转和口头猜测完成，成本高且不可复现：看完一遍仍说不清调用路径属于哪一层，也看不出模块是长期高频修改还是早已冻结。

## Solution

一个本地优先的桌面工具：一条命令索引目标仓库，生成版本化 JSON 产物；桌面端用分层模块地图呈现结构，支持点击下钻到符号级调用图，并按「入口 → 目标」播放一条引导式路径；另一条独立能力从 git 历史计算模块级演化指标，用时间线与热力呈现「长期反复修改」与「多年未动」。

交付形态为纯桌面端：Rust core + 独立 headless CLI + GPUI 桌面视图，共享 core；不做 Web UI，不导出可交互 HTML（ADR-0002）。所有解析在本地完成，不上传代码。

## User Stories

1. 作为一个第一次读陌生仓库的开发者，我想用一条命令生成目标仓库的结构产物，以便不启动 GUI 也能先确认工具能解析它。
2. 作为一个第一次读陌生仓库的开发者，我想看到仓库被分成哪些层，以便先建立「系统由什么组成」的整体印象。
3. 作为一个第一次读陌生仓库的开发者，我想看到目录语义推断不出的模块被显式列为 `unclassified`，以便知道工具哪里不确定，而不是被静默归类误导。
4. 作为一个第一次读陌生仓库的开发者，我想点击一个模块后看到它内部的符号，以便从「有哪些文件」下钻到「有哪些函数/组件/类」。
5. 作为一个第一次读陌生仓库的开发者，我想看到模块之间与符号之间的依赖边和调用边，以便区分「引用了」和「调用了」。
6. 作为一个第一次读陌生仓库的开发者，我想看到跨模块的 JSX 组件调用边，以便理解 React 项目里组件是怎么被组装的。
7. 作为一个第一次读陌生仓库的开发者，我想看到无法解析的导入被标记为 `unresolved` 并给出原因类别，以便判断工具的盲区而不是怀疑自己的理解。
8. 作为一个第一次读陌生仓库的开发者，我想让工具列出候选入口（`package.json` 的 main/bin/exports、`index.*`、公开导出），以便不必先读构建配置就能开始。
9. 作为一个第一次读陌生仓库的开发者，我想选定一个目标符号并让工具算出从入口到它的最短路径，以便直接回答「这个功能是怎么被触发的」。
10. 作为一个第一次读陌生仓库的开发者，我想让这条路径沿边播放并逐步追光，以便把注意力集中在当前这一步，而不是同时看整张图。
11. 作为一个第一次读陌生仓库的开发者，我想逐步前进/后退路径的每一步，以便按自己的节奏检查每一跳。
12. 作为一个第一次读陌生仓库的开发者，我想在路径播放时把非当前路径的节点和边淡出，以便减少视觉噪声。
13. 作为一个第一次读陌生仓库的开发者，我想一键关闭全部动画，以便在低配机器或专注阅读时得到静态画面。
14. 作为一个第一次读陌生仓库的开发者，我想在画布上平移、缩放、点击命中节点，以便在大图上定位而不迷路。
15. 作为一个第一次读陌生仓库的开发者，我想在缩得很小时隐藏标签、放大时恢复，以便在保持性能的同时可读。
16. 作为一个第一次读陌生仓库的开发者，我想看到每个模块的最近修改时间，以便知道哪些代码是「活的」。
17. 作为一个第一次读陌生仓库的开发者，我想看到每个模块在统计窗口内的提交次数与 churn，以便识别长期反复修改的热点。
18. 作为一个第一次读陌生仓库的开发者，我想看到模块首次出现的时间与活跃跨度，以便识别新近引入的模块和早已冻结的模块。
19. 作为一个第一次读陌生仓库的开发者，我想在时间线上拖动到某个历史提交并看到当时的模块热度，以便理解结构是怎样演化的。
20. 作为一个第一次读陌生仓库的开发者，我想让演化视图和静态结构图使用同一套模块标识，以便在两个视图之间来回对照而不混淆。
21. 作为一个第一次读陌生仓库的开发者，我想在 git 历史不可用（非 git 仓库、浅克隆、无提交）时得到明确的状态与原因，而不是空白视图。
22. 作为一个第一次读陌生仓库的开发者，我想确认工具不会修改目标仓库的工作区、索引或分支，以便放心在真实仓库上运行。
23. 作为一个第一次读陌生仓库的开发者，我想在目标仓库超过规模上限时得到明确的拒绝或降级提示，以便知道当前读数不可信。
24. 作为一个在 CI 或脚本里使用工具的开发者，我想用退出码区分「成功」「输入错误」「不可达路径」「内部错误」，以便可靠地串联命令。
25. 作为一个在 CI 或脚本里使用工具的开发者，我想让 JSON 产物带 schema 版本号，以便升级工具后能检测兼容性问题。
26. 作为一个在 CI 或脚本里使用工具的开发者，我想让同一输入重复运行产出字节一致的 JSON，以便做 golden 断言和 diff。
27. 作为一个维护者，我想让解析、图算法、历史统计都能通过 core 的公共接口单独测试，以便定位缺陷而不依赖 GUI。
28. 作为一个维护者，我想让 UI 的静态布局和交互状态可被结构断言与模拟事件验证，以便在 CI 里挡住回归；离屏截图为待定能力，由 ticket 11 重新定义。
29. 作为一个维护者，我想让历史指标能用系统 `git` 命令作为独立 oracle 交叉验证，以便不信任单一实现。
30. 作为一个维护者，我想在 GPUI 升级时通过固定版本 + `--locked` 构建并跑冒烟，以便把 pre-1.0 的破坏性变更挡在合并前。
31. 作为一个维护者，我想看到索引耗时、历史耗时与峰值内存的归档读数，以便判断性能预算是否仍然成立。
32. 作为一个注重隐私的开发者，我想确认工具全程离线、不读取 git remote、不上传代码或遥测，以便在私有仓库上使用。
33. 作为一个第一次读陌生仓库的开发者，我想在看完一条引导式路径后得到可复制的文字小结（经过的模块与符号序列），以便把结论贴进笔记或给同事。
34. 作为一个第一次读陌生仓库的开发者，我想在后续探索时（点击其他节点、切换时间线）保持当前上下文，以便不丢失刚建立的路径认识（本轮仅占位，细节待定）。

## Implementation Decisions

### 1. 总体架构与交付形态

- 三个产物：`arch-core`（解析、图模型、图算法、git 历史统计）、`arch-cli`（headless，唯一的 JSON 契约出口）、`arch-view`（GPUI 桌面视图）。CLI 与视图共享 core，不各自实现一套逻辑。
- 纯桌面端；无 Web 目标、无可交互 HTML 导出（ADR-0002）；不引入本地 HTTP 服务。
- 解析范围仅 TS/JS（`.ts`、`.tsx`、`.js`、`.jsx`、`.mjs`、`.cjs`），语言无关 IR 预留扩展点，但 MVP 不实现第二种语言。
- 所有数据本地处理；不访问 git remote、不发网络请求、不做遥测。

### 2. 图 IR 与 JSON 契约

- 双层节点：符号级为真相（函数、组件、类、方法、模块顶层），模块级为聚合视图；两级共用稳定的 ID 规范。
- 两类边：依赖边（模块/符号引用）与调用边（调用表达式、JSX 组件使用）；边上带 `kind` 与解析状态。
- 未解析项进入 `unresolved` 集合，带原因类别（外部包、动态导入、非 TS/JS 扩展、路径别名未命中、语法错误），且在 UI 中可见。
- 无法归因的调用（`call-unattributed`）默认只保留聚合计数 `stats.unattributedCalls`，不进入 `unresolved` 明细、不进入边列表/图、不参与路径查询；`arch-cli callgraph --include-unattributed` 输出完整明细供诊断。其余原因类别（`dynamic-import`、`external-call`、`unresolved` 导入）始终保留明细。
- 产物为版本化 JSON：顶层含 `schemaVersion`、工具版本、目标仓库标识（路径与 HEAD commit，若可用）、统计窗口与截断标记；集合字段排序固定。调用图为独立产物，使用独立的 `CALLGRAPH_SCHEMA_VERSION`（04c 起为 2：拆分统计 + `external-call` + 默认聚合）；`index` / `layers` 仍使用 `SCHEMA_VERSION = 1`，两者不共用版本号。
- 默认不写墙钟时间戳；如需时间戳，仅通过显式参数开启并排除在 golden 比较之外。

### 3. 模块解析

- 支持相对导入、`tsconfig` / `jsconfig` 的 `paths` 与 `baseUrl`、workspace 包（`package.json` workspaces / pnpm workspace）、`package.json` `exports` 的基础匹配。
- `node_modules` 收敛为包级节点，不展开到包内文件；内置 Node 模块单独标记。
- 动态 `import()` 与 `require()` 尽力解析；无法静态确定目标时入 `unresolved`，不猜测。
- 解析结果必须确定：同一输入两次运行边集合一致。

### 4. 符号与调用图

- 符号提取覆盖函数声明、箭头函数赋值、类与方法、导出组件；匿名函数以「所属符号 + 位置」生成稳定 ID。
- 调用边来自调用表达式与 JSX 使用；成员调用按可解析的接收者类型/导入绑定尽力归因，无法归因入 `unresolved`。
- 外部导入绑定（ES `import` 与 CommonJS `require()` 的解构/命名空间绑定同等对待）上的**成员调用与裸调用**均记为 `external-call`，不再落入 `call-unattributed`。
- 边界：不做类型推断；不猜测局部变量、函数参数、`any` 值上的成员调用归属；对象字面量方法定义不属于调用（当前可能误判，列入 backlog）。
- 模块级聚合边由符号级边收敛得到，聚合规则固定且可解释（同模块对去重、保留边种类集合）。
- 符号 ID 规范需在实现首票冻结：重载、默认导出、匿名函数、同名不同文件必须给出可复现规则。

### 5. 层推断

- 层来源为目录语义（如 `cli`、`commands`、`components`、`utils`、`server`、`tests` 等命名启发）加依赖方向校正（违反方向的边用于降低置信度，不静默改写）。
- 固定层集合（ticket 03 冻结，03b 增补 `external`）：`cli`、`commands`、`components`、`server`、`utils`、`tests`、`external`、`unclassified`；视图层带按此顺序自上而下排列。
- 规则优先级：外部包（`kind == external-package`）→ `external`；文件名后缀（`*.test.*` / `*.spec.*` → `tests`，`*.stories.*` → `components`）；目录段大小写不敏感、最深匹配优先；拓扑位置只在文件名规则冲突时断平。命名规则始终优先于拓扑。
- 目录匹配规则：`command/commands/action/actions`、`component/components/ui/hooks/renderer`、`util/utils/lib/common/shared`、`test/tests/__tests__/spec/specs` 互为同义；`app/apps` 与 `*-app` 视为应用外壳。`src/<第一段>`、`packages/*/src` 使用同一套目录规则，workspace 子包按包内目录判断。
- 外部包进入独立 `external` 层，携带原因码 `external`，不出现在 `unclassified` 列表；无匹配与命名冲突分别携带 `no-rule-match` / `ambiguous`。每个未归类模块必须可逐条解释，规则标识记录在 `rule` 字段。
- 方向规则：按外向程度排序 `cli > commands > components > server > utils`，`tests` 视为最外层；边从内向外的（源层外向程度低于目标层）标记 `directionAdjusted = true`，原边保留。
- 无法识别的模块进入 `unclassified`，必须在 CLI 产物与 UI 中同时可见；不允许默认归入某一层。
- 层推断只做一次全量计算，结果随结构产物输出，供视图与路径解释共用。

### 6. 引导式路径

- 入口候选来源：`package.json` 的 `main`/`bin`/`exports`、根级 `index.*`、`src/index.*`、公开导出（`export *`/`export {}`）。
- 用户选定入口与目标符号后，core 在调用图（为主）与依赖图（补足）上计算最短路径；多条等长路径按固定排序规则选一条，保证确定性。
- 路径产物包含有序的「模块 → 符号」步骤、每步的边种类与所属层；不可达时返回专用退出码与原因。
- 路径可输出为文字序列（用于复制与脚本断言），GUI 播放只是同一产物的呈现。

### 7. 历史演化（独立能力）

**数据来源**

- 只读 git 对象库：通过 `rev-list` / `diff-tree` 与读取 commit tree、blob（按 OID）完成，**不 checkout、不建工作树、不改动目标仓库**。
- 默认只走 **first-parent 链**：主线演化清晰、成本可控；合并提交的第二父分支改动不计入模块指标（在产物中声明该口径）。
- 默认窗口：最近 500 个 first-parent 提交，或最近 12 个月，先到者为准；可用参数覆盖 `--max-commits`、`--since`、`--until`。
- 重命名检测使用 `diff-tree -M`（相似度阈值固定），并把重命名前后的路径归并到同一模块谱系。

**成本控制**

- 惰性加载：先构建「提交 → 变更路径」轻量索引，模块指标按需计算；UI 只请求视口内与时间线当前刻度需要的模块。
- 只解析发生变更的 blob；未变更文件不重复解析；blob 按 OID 缓存，同一内容只算一次。
- 路径过滤：默认忽略 `node_modules`、构建产物目录、二进制与超长文件；忽略规则写入产物元数据。
- 可选采样：超过窗口上限时可按固定步长采样并显式标记 `sampled=true` 与采样率；采样结果不得伪装成全量。
- 截断与浅克隆必须显式报告：`truncated` / `shallow` 状态进入产物与 UI，不静默降级。

**指标（模块级）**

- `firstSeen`：模块（含重命名谱系）首次出现在窗口内的提交时间。
- `lastModified`：窗口内最后一次修改该模块的提交时间与 commit。
- `commitCount`：窗口内触及该模块的提交数（first-parent）。
- `churn`：窗口内该模块的增行 + 删行总数。
- `activeSpan`：`lastModified - firstSeen`。
- 聚合到模块级；文件级指标可作为中间量但不作为对外承诺。

**能回答 / 不能回答**

- 能回答：哪些模块长期被反复修改；哪些模块多年未动；某模块最后一次变更在何时；模块何时首次出现；窗口内变更量大小；重命名谱系。
- 不能回答：修改意图与质量、运行时行为、作者动机、跨分支演化、被 squash 掉的历史细节、合并提交第二父分支的改动。

**产物与呈现**

- `history.json` 为独立版本化产物，含 `schemaVersion`、窗口参数、采样/截断状态、模块指标集合。
- CLI 提供 `history` 子命令；GUI 提供时间线与模块热力视图。MVP 只要求静态呈现与按刻度刷新；演化动画与探索式交互先占位（见 ticket 13），不阻塞 MVP。

### 8. 渲染与交互（GPUI）

- 使用 GPUI 的 `canvas` prepaint/paint 自绘节点、边与标签；图布局自实现（分层布局优先），不依赖现成图库。
- 交互：平移、缩放、点击命中、悬停高亮、模块下钻、返回上一层；命中测试使用自维护的空间索引（网格或四叉树二选一，按实测决定）。
- 标签避让与边路由在 MVP 只做最低可用版本：标签按层分布 + 简单碰撞剔除，边用直线/简单曲线；不承诺正交路由。
- LOD：缩放到阈值以下隐藏标签与次要边，只保留层与模块骨架。
- 静态渲染的结构验收以布局模型断言为主（节点矩形、边端点、标签包围盒、z-order、命中框），不依赖窗口帧导出。
- **截图能力更正（2026-11-07）**：原文写「`Window::render_to_image` 产出图像用于结构断言」，实测 gpui 0.2.2 不存在公开离屏导出入口。截图相关验收已从 ticket 03 移除，移交 ticket 11 重新定义；当前未验证，不得记为通过。详见 `docs/acceptance-gaps.md` 第 2.2 节。

### 9. 动画策略

- MVP 只承诺 G1：引导式路径沿边播放 + 逐步追光 + 非路径元素聚焦/淡出；可选 fly-to（默认关）。
- G2 分层升起/边生长只在首屏播放一次且默认关闭；G3 morph / 双 commit diff 延后；G4 粒子流动与节点呼吸不做（演示好看但不解决理解，且易被误读为数据流）。
- 所有动画必须可一键关闭；关闭后不得再调度动画帧。
- 帧预算为 p95 ≤16.7ms（推荐值，待用户确认），只在播放期间计时，不在空闲帧计时。

### 10. CLI 契约与错误码

- 子命令：`index`（结构产物）、`callgraph`（符号与调用图，含 `--include-unattributed`）、`history`（演化产物）、`path`（引导式路径）、`layers`（层推断结果，便于脚本断言）。
- 成功 `0`；输入/参数错误 `2`；内部错误 `3`；路径不可达 `4`；历史不可用（非 git、无提交、浅克隆不满足）`5`。
- 所有成功输出为合法 JSON 到 stdout（或指定文件），诊断信息走 stderr；不得把日志混入 stdout。
- `--out` 指定产物路径；`--schema` 打印 `index` / `layers` 使用的 `SCHEMA_VERSION`；调用图版本只通过产物内的 `schemaVersion` 字段暴露；未知参数报错退出 `2`。

### 11. 配置与确定性

- 配置优先级：CLI 参数 > 目标仓库内工具配置 > 内置默认值；配置只读，不在目标仓库写入任何文件。
- 所有集合输出排序固定（模块按 ID、边按源/目标/种类、unresolved 按路径/原因）。
- 同一输入、同一工具版本、同一窗口参数下，JSON 字节级一致（golden 可 diff）。
- 路径与内存指标只在显式参数下输出。

### 12. 性能与资源

- 规模目标：目标仓库 ≤5k 文件、≤20k 符号；冷索引 <10s（Q6 已定）。超过上限时给出明确拒绝或降级标记，读数不得冒充达标。
- 内存：推荐硬上限 512MB（待用户确认），超限必须失败并给出已处理规模，不得 OOM 崩溃。
- 历史：默认窗口 500 first-parent 提交，`history` 在推荐样本仓上 ≤10s（待硬件基线与用户确认）。
- 性能读数以 3 次运行归档，取中位数与 p95；硬件基线随产物记录。

### 13. 跨平台

- Windows 为主验收平台；macOS 与 Linux 做编译 + 启动冒烟（待用户确认平台矩阵）。
- GPUI 固定版本（推荐 `=0.2.2`）+ 提交 `Cargo.lock` + CI `--locked`；不启用自动依赖更新；升级单独 PR 并跑结构断言/冒烟回归（截图回归能力见 ticket 11，当前不可用；升级节奏待用户确认）。

## Testing Decisions

- 好测试的标准：只断言外部可观察行为（CLI JSON、core 公共 API 返回值、渲染图像与交互状态），不断言内部函数调用顺序或私有结构；golden 只在语义稳定后冻结。
- 测试 seam（按 `to-spec` 提出，实施前需与用户确认；本轮不阻塞拆票）：
  1. **最高 seam：CLI 子命令的 JSON 产物**。绝大多数解析、图结构、层、路径、历史指标都从这里断言；用 `assert_cmd` + JSON schema/结构比对。
  2. **次高 seam：`arch-core` 公共 API**。仅用于难以通过 CLI 构造的场景（图算法边界、路径排序、重命名谱系）。
  3. **视图 seam：布局模型断言 + 模拟事件**。布局模型提供节点矩形、边端点、标签包围盒、z-order、命中框，供确定性结构断言；`gpui::test` 的 `run_test`/`TestAppContext` 做点击、缩放、播放状态断言。离屏出图能力当前未建立（gpui 0.2.2 无公开离屏导出入口），截图路径由 ticket 11 选型。
- 模块覆盖：模块解析、符号/调用图、层推断、路径查询、历史统计各自有 core 测试；CLI 契约、视图布局、路径播放、时间线各有端到端测试。
- 样本与 oracle：
  - 结构测试固定样本：`privatenumber/tsx` @ `4473971f4b3261de253209b148d8fdc43269fcc4`；`excalidraw/excalidraw` @ `701b901a0f1ba3d0b390d9cdf63d112e25abac4b`（**R2-8 依据讨论稿倾向，未逐项确认**）。
  - 历史测试除固定样本外，另有本地构造的小型 git fixture（含重命名、合并、空提交），用于精确断言 first-parent 与重命名归并语义。
  - oracle：历史指标用系统 `git log` / `git rev-list --first-parent` / `--numstat` 的输出做交叉验证；结构指标用人工抽检的 golden 作为基线。
- 基线策略：首次运行生成 golden，人工抽检不少于 10 条边/10 个模块指标并签字；随后 CI 断言零漂移。任何口径变化必须显式更新 golden 并在 ticket 中记录原因。
- 无法自动验证的 6 项沿用 `docs/acceptance-gaps.md` 的替代口径与风险边界：峰值内存跨平台采集、GPU 截图 CI 稳定性、动画流畅度、用户理解、跨平台视觉一致性、GPUI 升级回归。
- 性能测试：CLI 墙钟用进程计时；内存用平台工具（Linux `/usr/bin/time -v`、macOS `/usr/bin/time -l`、Windows 轮询 `WorkingSet64`，后者为代理指标并标注置信度）。
- 测试不得依赖网络：样本仓以离线副本或固定归档进入测试环境；`git` 命令作为 oracle 时需在 CI 镜像中预装。

## Out of Scope

- Web UI、浏览器内交互、可交互 HTML 导出、本地 HTTP 服务。
- 数据流分析（赋值、参数、返回值传播）与运行时 trace。
- TS/JS 以外的语言；框架路由自动发现（Next.js / React Router 等）。
- 增量索引、文件监听 watch、持久化图数据库。
- 插件体系、第三方语言适配层。
- 作者分析、提交者统计、代码质量/复杂度评分。
- 符号级重命名历史、跨分支比较、两点 commit 结构性 diff（G3 动画同属延后）。
- 3D 视图、粒子流动等纯演示效果。
- 遥测、崩溃上报、云同步；一切网络请求。
- 可访问性（键盘全操作、屏幕阅读器）与国际化。
- 发布与分发方式（安装包、签名、自动更新）。
